# Changelog

All notable project changes are recorded here.

The project is pre-release. Versions and release dates must reflect actual published artifacts.

## Unreleased

### Added

- **Configuration secret references:** `@chainmcp/config` resolves `${VAR}` and `${VAR:-default}` in designated credential fields (inbound token/API-key records, JWT secret, static upstream credentials, OAuth `clientSecret`, `secretStore` keys, and Redis URLs/TLS keys) before schema validation. Missing variables fail with `SECRET_UNRESOLVED` naming the field and variable; resolved values are never logged. `resolveConfigSecrets` and `redactConfigSecrets` are exported.
- **`chainmcp config explain`:** Prints the resolved server configuration with every credential field replaced by `[REDACTED]`, plus value-free environment provenance per secret. `--json` emits `{ configPath, config, secretSources }`.
- **Local-clone dependency mode:** `chainmcp init` and `chainmcp export` accept `--local-deps <repo-root>`, emitting relative `file:` specifiers and a generated `pnpm-workspace.yaml` override block so the unpublished `@chainmcp/*` packages install from a cloned checkout with no registry access. `--workspace-deps` is now exposed on the CLI for in-repo projects; the two modes are mutually exclusive.
- **Runtime version stamping:** generated dependency ranges, the generated server's advertised version, and `manifest.generatorVersion` now come from the CLI's own `package.json` through `getCliVersion()` instead of the hardcoded `0.1.0`.

### Changed

- **Graceful HTTP shutdown (P0-5):** `serveHttp` now drains in-flight work instead of calling `closeAllConnections()` immediately. Shutdown marks the server as closing, answers requests that arrive during the window with `503` plus `Connection: close`, drains work-bearing `POST`/`DELETE` requests for up to `server.shutdownTimeoutMs` (default 10,000 ms; `0` skips the drain), then aborts the request cancellation signal so cooperative tools stop. Listener close, socket force-close, MCP handler teardown, `runtime.close()`, and `onclose` run once. SIGINT/SIGTERM are idempotent: the first signal sets exit code `130`/`143` and repeated signals do not re-run teardown. `GET`/`HEAD` streams such as SSE and health probes do not extend the drain budget.
- **Runtime teardown hooks:** `ToolRuntime.close?()` and `InMemoryToolRuntime.close()` flush `MetricsSink.flush?()` and run `RuntimeOptions.onShutdown()` exactly once (concurrency-safe, failure-isolated). `buildRuntimeOptions` uses `onShutdown` to drain the shared Redis client it created; caller-supplied clients are left untouched. `serveHttp` and `serveStdio` invoke `runtime.close()` after the transport closes.
- **Verified generated-server startup (P0-3):** generated servers now load `dist/compiled-tools.json` instead of recompiling the OpenAPI contract, after verifying the manifest schema version, generator/compiler versions, contract source hash and revision, tool count, artifact digest, and per-tool hashes. Drift fails startup with a remediation message; `--allow-manifest-drift` / `CHAINMCP_ALLOW_MANIFEST_DRIFT=1` downgrades it to a warning, and recompilation remains a `NODE_ENV=development` fallback so production startup never imports `@chainmcp/compiler`.
- `chainmcp build` now mirrors `chainmcp.manifest.json` and `compiled-tools.json` to the project root in addition to `--out-dir`, so generated servers can verify artifacts at startup. `SECRET_UNRESOLVED` is added to `CompileDiagnosticCode`.
- **Documentation truth pass for environment variables:** `CHAINMCP_DATABASE_URL`, `CHAINMCP_UPSTREAM_TIMEOUT_MS`, and `CHAINMCP_SECRET_PROVIDER` were documented but never implemented. They are removed from `CONFIGURATION.md` and `docs/deployment.md`; no runtime behavior changes.
- **Breaking for embedders:** `@chainmcp/cli` no longer exports `CLI_VERSION`; use `getCliVersion()`. `buildProjectManifest` and `buildCodeFirstManifest` now require a `generatorVersion` option.
- **Breaking for verifier callers (P0-6):** `InboundAuthVerifier.verify` may now return an `InboundAuthFailure` instead of `undefined` when a credential verifies but tenant context cannot be resolved. Callers must narrow with `isInboundAuthFailure()` before reading `context`. Custom verifier implementations returning `InboundAuthResult | undefined` remain assignable. `createInboundVerifier` accepts a second `settings` argument (`multiTenant`, `fallbackTenantId`).
- **Documentation truth pass (P0-8):** README now says the project is pre-1.0 and that the 1.0 release is deliberately withheld; registry `npx @chainmcp/cli` and bare `chainmcp` examples are marked as requiring publishing or an installed CLI (clone path is `node packages/cli/dist/bin.js`); intended technology no longer lists Hono or PostgreSQL (no database metadata store ships); token accounting, JSON navigation, response-schema enforcement, and auth-policy language match the shipped behavior; the generated-server Dockerfile and deployment install steps now use pnpm in local-deps mode; product-guide marketing claims, metric names, and JSON-navigation descriptions were softened to match the code.

### Added

- **Documentation drift guard (P0-8):** `pnpm docs:check` (wired into `pnpm check` and CI) validates that every documented capability in `docs/capability-evidence.json` points to a real test file or exported API, and that the README `## Core capabilities` bullets are all covered. The registry is the source of truth for this check.

### Security

- **P0-7 strict browser-origin defaults:** CORS is now disabled by default on every bind host, including loopback; `cors: true` without `allowedOrigins` remains disabled, and an explicit wildcard always warns at startup. Browser-origin validation is independent of CORS and always on: a request carrying an `Origin` outside the effective allowlist receives `403` before any tool runs, even when CORS headers are disabled. Requests without `Origin` (CLI clients) are unaffected. The Inspector UI can opt in with `allowedOrigins: ["http://localhost:6274"]`. Breakage: browser clients that relied on the old implicit loopback wildcard must configure their origin.
- **P0-6 JWT tenant resolution fails closed:** A verified JWT with no tenant claim and no explicitly configured fallback is now rejected as `TENANT_REQUIRED` instead of a generic unauthenticated response. Built-in verifiers return `InboundAuthFailure`, and `serveHttp` answers `401` with `error.data.code: "TENANT_REQUIRED"`, even when inbound auth is optional. `createJwtVerifier` gained `tenantClaim` (explicit claim name), `fallbackTenantId` (only for tokens without a claim), and `requireExplicitClaimMapping`. `createInboundVerifier({ multiTenant: true })` refuses construction without an explicit tenant mapping, so the dynamic gateway never guesses a tenant from implicit `tenantId`/`tid` claims. `config.tenant` / `--tenant` is passed to JWT verification as the documented fallback.
- **Credential-source interpolation (P0-4):** Credential fields no longer require literal secrets in `chainmcp.config.yaml`. Missing `${VAR}` references fail closed with `SECRET_UNRESOLVED` naming the field and variable (never the value), and `chainmcp config explain` redacts every designated secret field. Non-secret fields are not interpolated, resolved values are not recursive, and empty environment values fall back to `${VAR:-default}`.
- **RM-13 remove implicit default tenant fallback & multi-tenant isolation:** Removed implicit `"default"` tenant fallback across `@chainmcp/cli` (`serve`, `dev`, `gateway serve`, and generated server templates) and `@chainmcp/gateway`. Introduced `TENANT_REQUIRED` runtime error code in `@chainmcp/core` and `@chainmcp/server`. Calls requiring tenant context reject with `TENANT_REQUIRED` instead of guessing or falling back to a default tenant. Dynamic gateway mode verifies tenant resolution at startup, refusing to start without an inbound verifier (`auth.inbound`) or explicit tenant fallback (`--tenant` / `config.tenant`). Authenticated tenant claims strictly take precedence over CLI/config defaults (`authTenant ?? explicitTenant`). Gateway emits `tenant_resolution_failed` audit events when tenant resolution fails.
- **RM-04 configurable CORS allowlist & dynamic header computation:** Replaced arbitrary origin reflection with a configurable CORS allowlist (`server.cors` with `enabled`, `allowedOrigins`, `allowedHeaders`, `allowCredentials`, `maxAgeSeconds`). Enforced parse-time and startup rejection of wildcard origin `*` when `allowCredentials: true` is configured. Sandboxed `null` origin is rejected with 403 Forbidden on preflights and omitted from response headers unless explicitly listed in `allowedOrigins`. HTTP responses attach `Vary: Origin` whenever CORS is active. Dynamic header computation derives `Access-Control-Allow-Headers` from configured verifiers (`InboundAuthVerifier.headerNames`), custom headers, and defaults without drift. CORS defaults to disabled on non-loopback bindings and warns on wildcard loopback bindings.
- **RM-03 HTTP inbound auth fail closed & secure defaults:** Enforced fail-closed behavior for HTTP servers and gateways bound to non-loopback network interfaces (e.g. `0.0.0.0`, LAN/public IPs), refusing to start unauthenticated unless `security.allowUnauthenticatedHttp: true` (or `--allow-unauthenticated-http`) is explicitly configured. Added immediate startup fail-fast validation when `requireInboundAuth: true` or `authorizer: "scope"` is configured without a corresponding inbound verifier. Unauthenticated servers on loopback interfaces (`127.0.0.1`, `localhost`, `::1`) or with explicit overrides emit structured startup warnings detailing the host, port, exposed tool count, and configuration remedies. Resolved security posture is logged at startup.
- **RM-02 HTTP request size, Host, Origin, and DNS-rebinding limits:** Enforced pre-buffering `Content-Length` cap checks and streaming body chunk limits defaulting to 1 MiB (`maxRequestBytes`), rejecting oversized payloads with HTTP 413 without unbounded memory buffering. Added strict `Host` header syntax and presence validation (HTTP 400). Added DNS-rebinding and unauthorized host/origin protections via `allowedHosts`, `allowedOrigins`, and `enableDnsRebindingProtection` (HTTP 403) without echoing untrusted values in responses. Enforced HTTP server `requestTimeout` and socket termination on slow-body clients. Wired these options through `@chainmcp/config`, `@chainmcp/server`, CLI serve commands, and server templates.
- **RM-01 inbound verifier prototype-chain auth bypass fix:** Replaced prototype-walking `in` checks with own-property checks (`Object.hasOwn`) in `createBearerTokenVerifier` and `createApiKeyVerifier`. Added strict runtime validation for candidate principals (`validatePrincipal` requiring non-empty string `tenantId` and `principalId`, and string array `scopes`) across configured maps, custom `verifyToken`/`verifyKey` callbacks, and JWT `mapClaims`, ensuring malformed or prototype-derived credentials fail closed with HTTP 401 unauthenticated.

### Implementation

- **Post-1.0 descriptor persistence and rollback:**
  - Add `DescriptorRevisionStore` with `candidate → active → superseded/failed` records keyed by tenant and contract, one active record per pair, and duplication, transition, revision-count, and byte-limit validation.
  - Add `InMemoryDescriptorRevisionStore` as the default and `FileDescriptorRevisionStore`, which writes a versioned JSON snapshot through a `0600` temporary file, `fsync`, and atomic rename, validates the file schema on open, and enforces 10 MiB and 100-revision defaults. The file store is documented as single-writer.
  - Give admin revisions durable `dset_…` ids distinct from gateway `rev_…` ids, and link both in revision metadata.
  - Order publication as candidate write → gateway publish → activation so a store rejection prevents publication and a gateway rejection marks the candidate failed. Store failures return typed `ADMIN_STORE_FAILURE`, `ADMIN_REVISION_CONFLICT`, or `ADMIN_REVISION_UNKNOWN` responses.
  - Add `POST .../rollback` to revalidate a stored superseded revision, republish it as a new gateway revision, and record a new admin revision with `rollbackOf`, so rollback survives a restart and keeps history append-only.
  - Add `DeclarativeAdmin.restore()` to republish each bound contract's active stored revision after the gateway is constructed, reporting restored, skipped (`already_active`, `descriptors_invalid`), and failure entries instead of throwing.
  - Revalidate persisted descriptors on restore and rollback so a tampered or stale store fails closed, and add the `admin_rollback` and `admin_restore` audit events with admin and gateway revision ids.
  - Add console rollback-by-revision-id and tests for revision history, rollback, failed candidates, store rejection, tenant isolation, file permissions, snapshot versioning, restart restore, idempotent restore, and corrupt or oversized snapshots.
- **Post-1.0 self-hosted declarative admin:**
  - Add `@chainmcp/admin` with a Web-standard `DeclarativeAdmin.handle(Request)` handler and a loopback-first Node server (`startDeclarativeAdminServer`). Routes cover service metadata, health, bound contracts, active tools, revision history, validation, static preview, and publication.
  - Authenticate operators with deployment-issued bearer tokens that carry a unique non-secret id and an explicit tenant scope. Tokens must be at least 16 characters, are compared in constant time over SHA-256 digests, and are never minted, logged, echoed, or persisted; tenant scope is enforced before contract binding lookup.
  - Bind each tenant/contract pair to a destination policy, optional credential scheme map, optional credential provider, and limits. Descriptors may only reference configured schemes; they cannot add hosts, change the base URL, or carry credentials.
  - Validate and statically preview descriptor sets with stable diagnostics, duplicate-name detection, and executor lowering, without contacting the upstream API or mutating the gateway.
  - Publish by lowering a fresh `UpstreamExecutor` and `DeclarativeToolSource` and calling `DynamicGateway.publishContract({ tools })`, so tenant ownership, revision ids, activation, collision checks, runtime rebuild, and gateway audit are reused. The descriptor set and per-tool revisions are recorded in revision metadata.
  - Serve a dependency-free operator console with a strict CSP, no inline script, same-origin requests only, and page-memory-only tokens.
  - Add transport defenses before the handler runs: loopback default, refusal of non-loopback binds without `allowRemote`, `Host` allowlisting against DNS rebinding, and `Origin`/`Sec-Fetch-Site` same-origin enforcement; all responses are `no-store`.
  - Add admin audit events (`admin_validate`, `admin_preview`, `admin_publish`, `admin_auth_failed`, `admin_request_rejected`) that exclude tokens, arguments, and credentials, plus request/descriptor caps (1 MiB body, 10 MiB ceiling, 1,000 descriptors).
  - Add unit and integration tests for token authentication and scoping, diagnostics, previews, publication through the gateway, collisions, revision listing, malformed and oversized requests, CSP assets, Host/Origin rejection, loopback-only binding, and shutdown.
- **Post-1.0 declarative HTTP tool descriptors:**
  - Add `@chainmcp/declarative` with a closed `descriptorVersion: 1` JSON descriptor: tool name and description, audited object-root input schema, fixed HTTP method, relative path template, path/query/header/cookie parameter bindings, optional JSON request body, auth references, and policy (runtime scopes, read-only cache TTL, output field selection/token budget, timeout).
  - Validate descriptors at load time with stable `DeclarativeDescriptorError` codes and issue paths. Reject absolute URLs, dot segments and unmatched placeholders, unsupported or permissive schemas, unbound input properties, non-primitive parameter types, transport-owned or reserved headers, unknown auth schemes, scopes on non-OAuth schemes, GET bodies, non-JSON body media types, and cache on non-read methods.
  - Lower descriptors into `CompiledOperation` metadata for the existing `UpstreamExecutor`, preserving its exact host allowlist, address classification, DNS pinning and peer verification, same-host redirects, timeouts, response caps, credential injection, and JSON response handling.
  - Add `DeclarativeToolSource`/`createDeclarativeToolSource()` to validate a descriptor collection, reject duplicate names, and bind tools with deterministic `sha256:` descriptor revisions as `contractRevision`.
  - Add `parseDeclarativeToolDescriptor()` and `parseDeclarativeToolDescriptorJson()` (256 KiB cap) plus a deployment-supplied `DeclarativeAuthSchemeMap` that carries credential shape only; secrets stay in the executor's `UpstreamCredentialProvider`.
  - Export `isReservedRequestHeader()` and `isValidRequestHeaderName()` from `@chainmcp/executor` so descriptor load-time validation cannot drift from the executor's request rules.
  - Add deterministic unit and integration tests covering lowering, revision stability, path and schema rejection, auth references, output projection, credential injection, cancellation, duplicate names, and executor error mapping.

### Breaking changes

- `RateLimiter.check` now returns `RateLimitDecision` (`{ allowed: boolean }`) instead of `Promise<void>`. Throwing `RuntimeError("RATE_LIMITED")` no longer denies a call; it is treated as a limiter failure. The package is pre-1.0, so this change is recorded rather than deprecated. See `docs/adr/0006-stage-aware-policy-errors.md`.
- `RuntimeOptions.now` no longer measures `durationMs`; it only supplies the event `timestamp`. Inject `RuntimeOptions.monotonicNow` to control durations. The package is pre-1.0, so this change is recorded rather than deprecated.
- `ToolRuntime.listTools` accepts an optional `ToolContext`, and `RuntimeErrorCode` gained `CONFIG_INVALID` and `AUTH_REQUIRED`. `ToolDefinition` gained optional `ownerTenantId`. Existing single-tenant call sites are unaffected. See `docs/adr/0008-mcp-authorization-mapping.md`.
- `ToolRuntime` now requires a `tenantMode` declaration so adapters can select the listing strategy without depending on a concrete class. Custom runtime implementations must add the field; the package is pre-1.0, so this change is recorded rather than deprecated.

### Limitations

- No OpenAPI response-schema validation, CLI, gateway, credential provider, authentication enforcement, generated-server wiring, or concrete cache/auth/rate-limit adapter is included.
- `@chainmcp/compiler` output is operation metadata; `@chainmcp/executor` turns it into runnable tools. Response schemas and authentication policies are not enforced; input `oneOf`/`anyOf`/`not` composition, `const`, remote references, and formats outside the asserted set remain unsupported. Authentication enforcement remains Milestone 5 work; generated-server/CLI wiring remains Milestone 7 work.
- The core input validator supports only the subset documented in `API_REFERENCE.md`.
